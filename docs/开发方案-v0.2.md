## 二、登录流程

```
启动
 └─ 有 token？ ── 否 ──> 登录页
      │                    ├─ 服务器地址（IP 或 IP:端口）
      │                    ├─ 账号 / 密码
      │                    ├─ [登录]  或  [离线使用]
      │                    └─ 失败提示：连不上 / 账号密码错 / 服务器错误
      └─ 是 ──> 校验（可选 /api/auth/me）
                 ├─ 通过 → 工作台
                 └─ 401  → 清 token → 登录页
```

### 字段与默认值

| 字段 | 规则 |
|---|---|
| 服务器地址 | 允许 `192.168.1.10`、`192.168.1.10:8080`、`https://host` 三种写法；缺协议补 `http://`，缺端口不补（由你后端决定） |
| 账号 / 密码 | 明文输入，密码可切换显示；「记住账号」默认开，「记住密码」默认关 |
| 登录态 | token 存 `flutter_secure_storage`；服务器地址与账号存 `shared_preferences` |
| 失效处理 | 任何请求返回 401 → 清 token → 跳登录页并提示「登录已过期」 |

### 接口约定（可改）

```http
POST {baseUrl}/api/auth/login
Content-Type: application/json
{"username": "...", "password": "..."}

200 → {"token": "...", "user": {"id": "...", "name": "Kkui"}}
401 → {"message": "账号或密码错误"}
```

后续请求统一带 `Authorization: Bearer <token>`。

**这条约定是我先定的，如果你后端已经定了路径/字段，告诉我，改一行就行。**

## 三、主题：两个维度

### 维度 1 · 明暗（手动）

| 值 | 效果 |
|---|---|
| 浅色 | 背景 `#F7F5FA`，卡片 `#FFFBFE`，描边 `#E3E0E9` |
| 深色 | 背景 `#0E1015`，卡片 `#171A21`，描边 `#252A35` |

### 维度 2 · 主题色（6 选 1，手动）

| 名称 | 种子色 | 用于 |
|---|---|---|
| 紫（默认） | `#6750A4` | 导航选中、按钮、开关、勾选框、FAB |
| 蓝 | `#2F6FED` | 同上 |
| 青 | `#0E7C86` | 同上 |
| 绿 | `#3E7B52` | 同上 |
| 橙 | `#B4730A` | 同上 |
| 玫红 | `#B3325F` | 同上 |

> **模块色不随主题变**：生理期永远是粉、愿望单永远是金、待办永远是当前主题色系的辅助色。
> 原因：模块色是语义（经期=粉），用户换成绿主题时如果生理期也变绿，认知会乱。

实现：`ColorScheme.fromSeed(seedColor: 选中的色, brightness: 选中的明暗)`，两个维度共有 6×2 = 12 种组合，全部从一份 token 表生成，不手写 12 套。

深色下主题色要提亮一档（`#6750A4` → `#8B7CFF` 这类），否则在 `#0E1015` 上发闷。颜色表里每个主题色都配一个 `dark` 变体。

## 四、网络层

```
lib/core/network/
├─ api_client.dart      Dio 实例（baseUrl 来自登录）
├─ interceptors.dart    token 注入 / 401 处理 / 日志（仅 debug）
├─ api_result.dart      统一结果类型：Ok / Failure(kind, message)
└─ auth_api.dart        login / me / logout
```

规则：

1. **baseUrl 只有一个来源**：登录页输入的地址。切账号或改地址就重建 Dio。
2. **网络错误要翻译成人话**：`连接超时`、`连不上服务器（检查 IP 和端口）`、`账号或密码错误`、`服务器出错了`。
3. **401 的唯一出口**：清 token + 跳登录，不在每个页面各写一遍。
4. **离线可用**：登录页有「离线使用」，跳过网络直接进本地模式；之后接了真后端，这个入口可以保留作为演示模式。

### 明文 HTTP 的坑（必须配）

你用 IP 登录，大概率是 `http://`。两个平台默认都拦：

- **Android 9+**：`AndroidManifest.xml` 加 `android:usesCleartextTraffic="true"`（或只对开发域名放行）
- **iOS**：`Info.plist` 加 `NSAppTransportSecurity → NSAllowsArbitraryLoads = true`

这是开发期配置，上架前要收窄。如果后端是 https，这条跳过。
