## 二、技术选型

| 用途 | 选择 | 理由 |
|---|---|---|
| 状态管理 | `flutter_riverpod` | 模块隔离好，provider 可测试，不依赖 BuildContext |
| 路由 | `go_router` | 声明式 + `ShellRoute` 做底部导航，路由表可由模块清单生成 |
| 本地库 | `drift` | 类型安全、支持 `watch()` 自动刷新列表、迁移可控 |
| 日期 | `intl` | 中文日期格式 |
| 导出/导入 | `share_plus` + `file_picker` | 备份成 JSON |
| 代码生成 | `build_runner` + `drift_dev` | 仅 drift 需要 |

不引入：`get_it`（手写 `di.dart` 足够）、`freezed`（v0.1 数据类手写，接 API 时再加）、`table_calendar`（自己画，才控得住设计）。

## 四、数据模型（v0.1，已为同步预留）

### 空间与成员

```sql
spaces(id TEXT PK, name TEXT, kind TEXT)          -- kind: personal | shared
members(id TEXT PK, space_id TEXT, name TEXT, initial TEXT,
        color INTEGER, is_me INTEGER)
```

首次启动写入：个人空间 + 共享空间；共享空间里放「我」和占位的「Momo」。

### 业务表

```sql
todo_items(
  id TEXT PK, space_id TEXT,
  title TEXT, note TEXT, due_at INTEGER NULL,
  done_at INTEGER NULL, done_by TEXT NULL,
  created_by TEXT, created_at INTEGER,
  updated_at INTEGER, deleted_at INTEGER NULL, rev INTEGER DEFAULT 1
)

period_logs(                        -- 只写个人空间
  id TEXT PK, space_id TEXT,
  started_on INTEGER, ended_on INTEGER NULL,
  flow INTEGER, symptoms TEXT, note TEXT,
  created_at INTEGER, updated_at INTEGER, deleted_at INTEGER NULL, rev INTEGER
)

wish_items(
  id TEXT PK, space_id TEXT,
  title TEXT, price INTEGER, priority INTEGER, link TEXT, note TEXT,
  created_by TEXT, created_at INTEGER,
  updated_at INTEGER, deleted_at INTEGER NULL, rev INTEGER
)

wish_savings(                       -- 按人拆分攒钱
  id TEXT PK, wish_id TEXT, member_id TEXT,
  amount INTEGER, saved_at INTEGER,
  updated_at INTEGER, deleted_at INTEGER NULL, rev INTEGER
)

module_settings(module_id TEXT PK, enabled INTEGER, visibility TEXT)
```

**为什么每张表都带 `space_id / updated_at / deleted_at / rev`**：等你写好后端，同步只需要「按 updated_at 拉增量 + 整行后写覆盖」，不用改表结构。v0.1 这些字段是本地写死的，不联网。

**共享是真的共享吗**：v0.1 不是。Momo 是本地占位成员，用来把「谁建的 / 谁完成的 / 各攒了多少」这套 UI 和数据跑通。真共享排在 M6，依赖你的 API。

## 五、主题实现

同一个 `ColorScheme.fromSeed`，浅色用原方案，深色用夜间 token：

| 角色 | 浅色 | 深色 |
|---|---|---|
| primary | `#6750A4` | `#8B7CFF` |
| background | `#F7F5FA` | `#0E1015` |
| surface | `#FFFBFE` | `#171A21` |
| outline | `#E3E0E9` | `#252A35` |
| onSurface | `#1C1B1F` | `#E7EAF2` |
| 生理期 | `#B3325F` / `#FBE7EF` | `#F472B6` / `#2A1A24` |
| 愿望单 | `#9A6A12` / `#FFF2D9` | `#F0B23E` / `#2A2214` |

模块主题色放进 `AppModule`（`accent` / `accentSoft`），并且**随亮度切换**——所以它是个函数 `accent(BuildContext)`，不是常量。

深色模式的两个坑：卡片与背景只差一档，必须留 1px 描边；强调色在深底上要提亮（`#B3325F` → `#F472B6`）。

## 六、模块契约

```dart
abstract class AppModule {
  String get id;                    // 'todo'
  String get name;                  // '待办'
  IconData get icon;
  String get route;                 // '/todo'
  int get order;
  SpaceKind get space;              // personal | shared
  Color accent(Brightness b);
  Color accentSoft(Brightness b);

  Future<void> onInit(ModuleContext ctx);
  Future<void> onDispose();
  Widget buildPage(BuildContext context);
}

class ModuleContext {
  final String moduleId;
  final AppDatabase db;
  final Space space;                // 该模块绑定的空间
  final GoRouter nav;
  final AppPrefs prefs;
  final EventBus events;
}
```

`registry.dart` 里一行一个模块，外壳（导航、路由、宫格、最近打开）全部由它生成。

## 八、风险与取舍

| 风险 | 处理 |
|---|---|
| drift 首次代码生成踩版本冲突 | 先做 M0 的一半：只加依赖 + 一张表，跑通 `build_runner` 再铺开 |
| 生理期算法没有明确规则 | 默认「最近 3 次周期平均」，无历史时 28 天；预测区间按 ±2 天显示为「预计」 |
| 双人共享做出「假同步」 | 明确不做：v0.1 里 Momo 是本地占位，UI 标「本地演示」，避免你以为已经能跨设备 |
| 深色模式对比度不足 | 统一用 token，不手写颜色；M5 专门过一遍深色截图 |
| 首页周期卡依赖生理期模块 | 生理期被关闭时，首页那张卡自动降级为「今日待办」摘要 |
| 包名/应用名要改 | 延后到上架前；改名会动签名，现在改纯属自找麻烦 |
