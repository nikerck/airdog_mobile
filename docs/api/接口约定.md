# 接口约定 v1.0（实现级）

> **这份文档是前后端的共同契约。** 后端按它实现，客户端按它接入；
> 任何一方想改字段，先改这里，再改代码。
>
> 机器可读版本：[openapi.yaml](openapi.yaml)　冒烟脚本：[smoke.sh](smoke.sh) / [smoke.ps1](smoke.ps1)

---

## 0. 怎么用

| 角色 | 用法 |
|---|---|
| 后端 | 按第 1–8 节实现；用第 10 节的验收清单自测，跑 `smoke.sh` 全绿即视为可接入 |
| 客户端 | 按第 9 节改三个地方（`ApiClient`、Repository、文件缓存）；开发期 `USE_MOCK=true` |
| 双方 | 字段名、单位、错误码以本文为准；`openapi.yaml` 是同一份内容的结构化版本 |

**v1 的硬约束**（为了不改客户端现有代码）：

1. 认证方式、信封结构、错误码必须完全一致（第 1.4、2 节）。
2. 空间 id 固定为 `sp_personal` / `sp_shared`，成员 id 固定为 `u_me` / `u_momo`（第 3 节）。
3. 时间一律毫秒时间戳，金额一律整数分。
4. 所有业务表必须有 `updatedAt / deletedAt / rev` 三个同步字段。

## 1. 通用约定

### 1.1 地址

```
http://<用户填写的 IP 或域名>[:端口]/api/...
```

- 客户端把用户输入的 `192.168.1.10:8080` 归一化成 `http://192.168.1.10:8080`，**不带 `/api`**。
- 所有业务接口都在 `/api` 下，服务端不要额外加前缀（如 `/v1`）。
- 开发期允许 http；上线建议 https。

### 1.2 请求头

| 头 | 必填 | 说明 |
|---|---|---|
| `Authorization` | 除登录外 | `Bearer <token>` |
| `Content-Type` | POST/PATCH | `application/json; charset=utf-8` |
| `X-Client` | 否 | 客户端会带 `airdog-mobile/0.1`，便于后端区分来源 |
| `Idempotency-Key` | 否 | 仅 `POST`，建议 24h 内去重 |

### 1.3 数据类型

| 概念 | 约定 | 例子 |
|---|---|---|
| 时间 | **毫秒时间戳 int64**（UTC 毫秒，不带时区） | `1761292800000` |
| 金额 | **整数分** | `189900` = ¥1899.00 |
| ID | 字符串，服务端生成 | `todo_1761292800000`、`file_abc123` |
| 布尔 | JSON `true/false` | |
| 空值 | `null`，不要用空字符串代替 | `"dueAt": null` |

> 客户端数据库里存的就是毫秒（drift `DateTime` → int），后端直接存 int64 即可，不要转字符串。

### 1.4 统一响应与错误码

**所有**接口（包括错误）都返回这个信封：

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code = 0` 成功；非 0 为业务错误码。
- `message` 会直接显示给用户，**必须是中文人话**。
- 失败时 `data` 为 `null`。

| HTTP | code 段 | 含义 | 客户端行为 |
|---|---|---|---|
| 200 | 0 | 成功 | 取 `data` |
| 400 | 1002 / 2xxx | 参数错误 | 弹 message |
| 401 | 1001 / 1003 | 账号密码错 / token 失效 | 清 token 回登录页 |
| 403 | 1004 / 2xxx | 无权限 | 弹 message |
| 404 | 9004 | 资源不存在 | 弹 message |
| 409 | 2xxx / 9002 | 版本冲突 | 提示「数据已更新」并重拉 |
| 413 | 5001 | 文件过大 | 提示换图 |
| 500 | 9001 | 服务端异常 | 弹「服务器出错了」 |

**错误码全表**

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 1001 | 401 | 账号或密码错误 |
| 1002 | 400 | 缺少必填参数 |
| 1003 | 401 | token 无效或已过期 |
| 1004 | 403 | 无权访问该空间/资源 |
| 2001 | 400 | 待办标题为空或过长 |
| 2002 | 403 | 非创建人不能修改内容 |
| 2003 | 409 | 待办版本冲突 |
| 3001 | 400 | 经期日期不合法 |
| 3002 | 409 | 已有未结束的经期记录 |
| 3003 | 403 | 经期数据不能写入共享空间 |
| 4001 | 400 | 愿望字段不合法 |
| 5001 | 413 | 文件超过 10MB |
| 5002 | 400 | 文件类型不支持 |
| 9001 | 500 | 服务端异常 |
| 9002 | 409 | 版本号不匹配 |
| 9004 | 404 | 资源不存在 |

### 1.5 列表与分页

列表接口统一返回：

```json
{ "code":0, "data": {
    "items": [ ... ],
    "serverTime": 1761300000000,
    "hasMore": false,
    "nextSince": null
}}
```

- `serverTime`：服务端当前毫秒时间，客户端用它校准增量同步的游标。
- 列表默认按 `updatedAt DESC`（最近改的在前）；同步接口按 `updatedAt ASC`。
- `limit` 默认 200，最大 500。

### 1.6 幂等

- `POST` 带 `Idempotency-Key: <uuid>`，24h 内同 key 必须返回**首次**的结果（相同 id），不能重复插入。
- `DELETE` 幂等：删除已删除的资源返回 200，不报 404。

## 2. 认证

### 2.1 登录

```http
POST /api/auth/login
Content-Type: application/json

{ "username": "zyy", "password": "123456" }
```

成功：

```json
{ "code":0, "message":"ok", "data": {
    "token": "eyJhbGciOi...",
    "expiresAt": 1763884800000,
    "user": { "id": "u_me", "name": "Zyy", "initial": "Z" } } }
```

失败：

```json
401 { "code":1001, "message":"账号或密码错误", "data":null }
```

规则：

- `token` 建议 JWT（HS256/RS256 都行），**有效期 30 天**，`expiresAt` 必须返回（客户端不解析 token，只存）。
- 密码用 bcrypt/argon2 存哈希；接口不区分「账号不存在」和「密码错误」。
- 登录接口限流：同一 IP 每分钟 5 次，超出返回 `429` + `code:9002`。

### 2.2 当前用户

```http
GET /api/auth/me
```

```json
{ "code":0, "data": { "user": { "id":"u_me", "name":"Zyy", "initial":"Z" } } }
```

### 2.3 登出

```http
POST /api/auth/logout
```

服务端把该 token 加入黑名单（或直接用短 TTL + 客户端丢弃）。客户端无论成功失败都会清本地 token。

### 2.4 客户端现有的会话行为（后端需要兼容）

- token 存在手机安全存储里，启动时读出来直接进主页，**不校验**；等第一个业务请求返回 401 才回登录页。
- 所以：**token 过期后，第一个业务请求必须返回 401 + code 1003**，客户端才会正确跳登录。

## 3. 空间与成员

```http
GET /api/spaces
```

```json
{ "code":0, "data": { "spaces": [
  { "id":"sp_personal", "name":"我", "kind":"personal",
    "members":[{"id":"u_me","name":"Zyy","initial":"Z","isMe":true}] },
  { "id":"sp_shared", "name":"我们", "kind":"shared",
    "members":[{"id":"u_me","name":"Zyy","initial":"Z","isMe":true},
               {"id":"u_momo","name":"Momo","initial":"M","isMe":false}] }
]}}
```

**v1 固定约定（重要）**

| 项 | 值 |
|---|---|
| 个人空间 id | `sp_personal` |
| 共享空间 id | `sp_shared` |
| 我 | `u_me` |
| 伴侣 | `u_momo` |

客户端现在用常量写死这四个值（`lib/core/db/app_database.dart` 的 `Spaces` / `Members`）。
后端必须使用同样的 id，否则需要改客户端常量。v1 只支持「一对一」共享，不支持多于 2 人。

**权限**

- 个人空间：只有 `u_me` 能读写。
- 共享空间：`u_me` 和 `u_momo` 都能读写；但「改内容」受第 5.4 节限制。

## 4. 文件（图片）

图片不进 JSON。先上传拿 `fileId`，再把 id 挂到待办上。

### 4.1 上传

```http
POST /api/files
Content-Type: multipart/form-data
Authorization: Bearer <token>

字段名：file
```

```json
{ "code":0, "data": {
    "id": "file_9f2c1a",
    "url": "http://192.168.1.10:8080/files/file_9f2c1a.jpg",
    "width": 1080,
    "height": 1440,
    "size": 312345,
    "sha256": "9f2c1a..." } }
```

校验：

| 项 | 规则 | 失败 |
|---|---|---|
| 大小 | ≤ 10 MB | 413 / 5001 |
| 类型 | `image/jpeg`、`image/png`、`image/webp` | 400 / 5002 |
| 数量 | 单次 1 个文件（客户端循环上传） | — |

规则：

- **按 sha256 去重**：同一用户上传同一张图，直接返回已有 id，不重复落盘。
- 存储：v1 建议存服务器本地磁盘 `<data>/files/<id>.<ext>`，由 Nginx/静态路由暴露；换 S3 只需改 `url` 生成方式，接口不变。
- 文件名只允许服务端生成，**不要用客户端文件名**（防路径穿越）。

### 4.2 读取

```http
GET /api/files/{id}
→ 200 image/jpeg（或 302 到 CDN）
```

不带 `Authorization` 也要能读（因为 `<img>` / `Image.network` 不方便带头）。
实现建议：id 用不可猜的随机串（≥ 16 位），作为「凭 URL 访问」的凭证。

### 4.3 删除

```http
DELETE /api/files/{id}
→ 200 { "code":0 }
```

仅允许删除自己上传且未被引用的文件；被待办引用时返回 `409`（或服务端做引用计数，v1 可不实现，客户端也不会调）。

## 5. 待办

### 5.1 列表

```http
GET /api/todos?spaceId=sp_shared&status=all&since=<ms>&limit=200
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `spaceId` | 是 | `sp_personal` 或 `sp_shared` |
| `status` | 否 | `all`（默认）/ `open` / `done` |
| `since` | 否 | 只返回 `updatedAt > since` 的行（含墓碑） |
| `limit` | 否 | 默认 200，最大 500 |

```json
{ "code":0, "data": {
  "serverTime": 1761300000000,
  "items": [
    { "id":"todo_1761300000000", "spaceId":"sp_shared",
      "title":"交房租",
      "content":"这个月 3200，转账后截图存底",
      "images":["file_9f2c1a","file_ab12cd"],
      "dueAt":1761292800000,
      "doneAt":null, "doneBy":null,
      "createdBy":"u_me",
      "createdAt":1761200000000, "updatedAt":1761200000000,
      "deletedAt":null, "rev":1 }
  ],
  "hasMore": false, "nextSince": null }}
```

排序：`doneAt IS NULL` 在前 → `dueAt` 升序（null 在后）→ `createdAt` 升序。
（客户端本地就是这样排的，后端保持一致，切到远端时列表不会跳。）

### 5.2 新建

```http
POST /api/todos
Idempotency-Key: 3f1c...

{ "spaceId":"sp_shared",
  "title":"交房租",
  "content":"这个月 3200",
  "images":["file_9f2c1a"],
  "dueAt":1761292800000 }
```

| 字段 | 必填 | 校验 |
|---|---|---|
| `spaceId` | 是 | 必须是调用者可见的空间 |
| `title` | 是 | 去空白后 1–120 字 |
| `content` | 否 | ≤ 5000 字，默认 `""` |
| `images` | 否 | fileId 数组，≤ 9 个，顺序即展示顺序 |
| `dueAt` | 否 | 毫秒时间戳 |

服务端补：`id`、`createdBy`（=调用者）、`createdAt`、`updatedAt`、`rev=1`、`doneAt=null`。

返回：`{ "code":0, "data": { "item": { ...完整对象 } } }`

### 5.3 修改

```http
PATCH /api/todos/{id}

{ "title":"交房租（已转）", "content":"...", "images":["file_9f2c1a"],
  "dueAt":null, "rev":3 }
```

- **只传要改的字段**，未传的保持不变。
- `dueAt: null` 表示**清除到期时间**（和「不传」不同，后者是不改）。
- `images` 传数组即整体替换（不是追加）。
- `rev` 必须传，服务端比对：不一致 → `409 / 2003` 并返回当前对象，客户端据此刷新。
- 成功返回 `{ "code":0, "data": { "item": {...} } }`（`rev` 已 +1）。

### 5.4 权限（必须实现）

| 操作 | 创建人 | 其他人（Momo） |
|---|---|---|
| 改 `title / content / images / dueAt` | ✅ | ❌ 403 / 2002 |
| 改 `doneAt / doneBy`（勾完成） | ✅ | ✅ |
| 删除 | ✅ | ✅（共享空间里都能删） |

判断依据：`createdBy == token.user.id`。客户端 UI 也按这个隐藏「编辑」按钮，但服务端必须自己校验一遍。

### 5.5 删除

```http
DELETE /api/todos/{id}
→ 200 { "code":0 }
```

软删除：写 `deletedAt = now`、`updatedAt = now`、`rev + 1`。重复删除返回 200。

## 6. 生理期（仅个人空间）

### 6.1 列表

```http
GET /api/period/logs?since=<ms>
```

```json
{ "code":0, "data": {
  "serverTime":1761300000000,
  "items":[
    { "id":"period_1761000000000",
      "startedOn":1761004800000,
      "endedOn":1761350400000,
      "flow":2,
      "symptoms":["cramp","headache"],
      "note":"",
      "createdAt":1761000000000, "updatedAt":1761000000000,
      "deletedAt":null, "rev":1 }
  ],
  "hasMore": false }}
```

排序：`startedOn ASC`（客户端要按时间顺序算周期）。

### 6.2 新建

```http
POST /api/period/logs

{ "startedOn":1761004800000,
  "endedOn":null,
  "flow":2,
  "symptoms":["cramp"],
  "note":"" }
```

| 字段 | 必填 | 校验 |
|---|---|---|
| `startedOn` | 是 | 当天 00:00 的毫秒；不能晚于今天 |
| `endedOn` | 否 | ≥ `startedOn`；不能晚于明天；`null` = 还在经期中 |
| `flow` | 否 | 0–3，默认 2 |
| `symptoms` | 否 | 枚举：`cramp` `headache` `fatigue` `mood` `backache` `insomnia` |
| `note` | 否 | ≤ 2000 字 |

规则：

- **写入的 `spaceId` 必须是 `sp_personal`**；传 `sp_shared` 直接 `403 / 3003`。服务端不信任客户端传的空间。
- **同一时间只能有一条未结束记录**：已有 `endedOn = null` 的记录时再建一条未结束的 → `409 / 3002`。

### 6.3 修改 / 删除

```http
PATCH  /api/period/logs/{id}    { "endedOn":1761350400000, "rev":1 }
DELETE /api/period/logs/{id}
```

`endedOn: null` 表示「撤销结束，回到经期中」。

### 6.4 周期计算在哪

**放在客户端**（`lib/modules/period/domain/period_calculator.dart`）。后端只存原始记录，不算周期。
理由：算法会调（已在 3 版里改过一次），放两端必然不一致。

若以后要在服务端出周报，规则：周期长度 = 最近 3 次开始日期间隔平均（只取 15–60 天的间隔），
经期长度 = 最近 3 次已结束记录的平均，无历史时 28 / 5。

## 8. 增量同步（v2，先设计好）

```http
GET /api/sync/changes?since=1761200000000&limit=500
```

```json
{ "code":0, "data": {
  "serverTime": 1761300000000,
  "hasMore": true,
  "nextSince": 1761299000000,
  "todos":[...], "periodLogs":[...], "wishes":[...], "savings":[...], "files":[...]
}}
```

规则：

1. 返回 `updatedAt > since` 的所有行，**按 `updatedAt ASC`** 排序，凑满 `limit` 就返回 `hasMore=true` 和 `nextSince`（=本页最后一行的 `updatedAt`）。
2. **墓碑行必须返回**（`deletedAt != null`），否则客户端删不掉。
3. `updatedAt` 由**服务端**生成，客户端上传的 `updatedAt` 一律忽略。
4. 冲突策略：客户端按 `rev` 发 `PATCH`，服务端 409 → 客户端丢掉本地改动、用服务端版本覆盖（v1 就是「后写覆盖」，不做字段级合并）。
5. 时钟：客户端只用 `serverTime` 作为下次 `since`，不用手机时间。

## 9. 客户端接入点（后端可据此判断「接得上」）

客户端已经把「网络层」和「数据层」分开了，接后端只动这几处：

| 文件 | 现在 | 接入时要做什么 |
|---|---|---|
| `lib/core/network/api_client.dart` | Dio + 信封解包 + 错误翻译 | 不用改；后端符合本文即可 |
| `lib/core/network/mock_interceptor.dart` | 只有 login 的假数据 | 后端就绪后加 `--dart-define=USE_MOCK=false` 关闭 |
| `lib/modules/todo/data/todo_repository.dart` | 直接读 drift | 加 `TodoApi`，改成「本地写 + 后台推送」 |
| `lib/modules/period/data/period_repository.dart` | 直接读 drift | 同上 |
| `lib/core/db/tables.dart` | 待办 `images` 存本地路径 | 加 `file_cache(file_id, local_path, sha256)`，`images` 改存 fileId |
| `lib/core/auth/auth_api.dart` | 只有 login | 加 `me()`、`logout()` |

**字段对照（客户端 ↔ 服务端）**

| 客户端（drift） | 服务端 JSON | 备注 |
|---|---|---|
| `TodoItem.title` | `title` | |
| `TodoItem.content` | `content` | |
| `TodoItem.images`（换行分隔的本地路径） | `images`（fileId 数组） | 接后端时要迁移 |
| `TodoItem.dueAt`（DateTime） | `dueAt`（int 毫秒） | 直接互转 |
| `TodoItem.rev` | `rev` | |
| `PeriodLog.symptoms`（逗号分隔字符串） | `symptoms`（数组） | `split(',')` ↔ `join(',')` |
| `PeriodLog.flow`（int 0–3） | `flow` | |

**客户端已知的行为（后端不要"优化"掉）**

- 客户端不发 `updatedAt`，只发 `rev`。
- 客户端对 401 的反应是**清 token 并回登录页**，不做静默刷新。
- 客户端本地是「先写库、再渲染」，所以后端 409 时页面不会卡住，只是提示一下。

## 10. 验收清单（后端 DoD）

后端交付前，逐条跑通（`smoke.sh` 覆盖了 1–12）：

1. `POST /api/auth/login` 正确密码 → 200 + token + expiresAt；错误密码 → 401 + code 1001。
2. 无 token 请求 `/api/todos` → 401 + code 1003。
3. `GET /api/spaces` → 两个空间，id 分别是 `sp_personal` / `sp_shared`。
4. `POST /api/files` 传一张 jpg → 返回 id/url/sha256；重复传同一张 → 返回**同一个 id**。
5. `POST /api/todos` 带 content + 2 张图 → 返回完整对象，`rev=1`。
6. `PATCH /api/todos/{id}` 改 title + `rev=1` → 成功，`rev=2`；再用 `rev=1` 改 → 409 + code 2003。
7. 用 Momo 的 token 改上面那条的 `title` → 403 + code 2002；改 `doneAt` → 成功。
8. `DELETE /api/todos/{id}` → 200；再 GET 列表不包含它；带 `since` 的同步接口**包含**它的墓碑行。
9. `POST /api/period/logs` 传 `spaceId=sp_shared` → 403 + code 3003。
10. 已有未结束经期时再建一条未结束 → 409 + code 3002。
11. `GET /api/sync/changes?since=0` → 所有表的数据 + `serverTime`；`hasMore` / `nextSince` 正确。
12. 所有错误响应的 `message` 是中文、可直接显示。

**两个要注意的实现细节**

1. **PATCH 用「裸值」，不是 `{isSet, value}`**

   Swagger 里 `UpdateTodoRequest` 把字段显示成 `Patch<T>` 对象：

   ```json
   { "title": { "isSet": true, "value": "改过" }, "rev": 1 }
   ```

   **这样发会返回 400 / 1002。** 后端注册了 `PatchJsonConverterFactory`，把 Patch 序列化成裸值，
   正确写法是：

   ```json
   { "title": "改过", "rev": 1 }
   { "dueAt": null, "rev": 2 }
   ```

   Swagger 的 schema 是类型反射的结果，不代表线上格式——以本文为准。

2. **409 会带回服务端当前对象**

   ```json
   { "code": 2003, "message": "待办已被修改，请刷新后重试",
     "data": { "item": { ... } } }
   ```

   客户端拿到 409 时可以不额外请求，直接用 `data.item` 覆盖本地。当前实现更保守：
   收到 409 先跑一次 `pullAll()` 再提示用户。

3. **`POST /api/files` 返回的 `url` 用的是服务端收到的主机名**

   从手机访问时可能拿到 `http://localhost:8080/...`（不可达）。客户端**只用 `id`**，
   需要图片时走 `GET /api/files/{id}` 用自己的 baseUrl 拼地址，别直接存 `url`。
